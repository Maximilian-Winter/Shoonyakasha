# Canvas UI

A plan for a retained, canvas-based UI system that draws either to the screen
or into a texture shown on a quad in the world. It adds Unicode text through an
SDF glyph atlas, batched drawing, clip rects, mouse hit testing, and a small
set of widgets.

## Where the 2D layer stands

What exists and keeps working unchanged:

- `Sprite2DComponent`, `UIAnchorComponent` (nine anchors plus a pixel
  offset) and `UILayoutSystem`, which writes the resolved anchor into
  `TransformComponent::position` (`include/ECS/Sprite2DComponents.h`,
  `include/ECS/UILayoutSystem.h`).
- `Text2DComponent` and `TextRenderSystem`, which turn each glyph into its own
  sprite entity. The glyphs come from `FontLoader`, a `stb_truetype` RGBA
  coverage atlas for ASCII 32–126 (`include/Resources/FontLoader.h`).
- `ApplicationBase::createUIPanel` / `createText` and their Python wrappers
  `engine.create_ui_panel` / `engine.create_text`.

What is missing for a canvas system:

| # | Gap | Where | Effect |
|---|-----|-------|--------|
| 1 | One `vkCmdDrawIndexed` per entity; no batching. | `FrameGraphRenderer::executeGeometryPass` | A text label costs one draw per glyph. |
| 2 | No parent/child rect layout. | `UILayoutSystem` | Elements can't size or position relative to a panel. |
| 3 | Text covers ASCII only, with no wrapping or vertical alignment. | `FontLoader`, `TextRenderSystem` | Non-Latin labels are pre-rendered to PNG with Pillow (dakini temple). |
| 4 | No scissor in the sprite path. | sprite pipeline | No clipping for panels or lists. |
| 5 | No hit testing or widgets. | `docs/guides/sprites-ui-text.md` | Every example builds its own interactions on raw input. |
| 6 | No screen-to-world ray. | — | World-space UI can't be clicked. |
| 7 | A pass can see only the main camera, and material textures are `GPUTexture`s, not graph images. | `SceneContext`, `MaterialComponentV5` | No existing way to render UI into a texture and sample it on a mesh. |
| 8 | No per-frame dynamic vertex buffer. `StagingBufferManager` is for SSBOs only; `createTexture2DWithData` calls `vkQueueWaitIdle`. | `include/GPU/` | Rebuilding UI geometry each frame has nowhere to go. |

## Frame graph facts the design relies on

- `registerGeometryRenderer(type, fn)` is only called for passes whose
  `executionKind` is `SceneRenderer`. `executionKindOf` maps any type it
  does not know to `Unknown`, and an `Unknown` pass logs a warning and draws
  nothing (`FrameGraphCompiler.cpp:37-46`). A new `"ui_canvas"` type
  therefore needs one line there. It must not be added to
  `isEntityGeometryExecutionType`.
- The callback gets a `PassExecuteContext` with the command buffer and
  `renderExtent`, after rendering has already begun on the pass's
  attachments. When the pass declares no shaders, the compiler builds no
  pipeline and the executor sets no viewport or scissor. The callback binds
  its own pipeline and sets scissor per batch.
- `color_blend` together with `present: true` on the swapchain is supported
  and tested (`tests/unit/FrameGraphPresentUsageTest.cpp`). The showroom
  pipeline already draws an overlay this way after Tonemap.
- Graph images are created at compile time, so a graph image per canvas would
  mean a recompile whenever a canvas is added or removed. Material textures
  are bound assuming `SHADER_READ_ONLY_OPTIMAL`, and graph barriers don't see
  them.
- The frame is recorded as `record(cmd)` → `m_renderGraph->execute(...)`
  (`ApplicationBase.cpp:490-491`), after the fence wait. Work recorded
  between those two calls runs before every graph pass.
- The material descriptor cache is keyed by image view and never evicts. A
  canvas texture that is destroyed and recreated needs an explicit release.
- `CameraComponent::projectionMatrix` is unflipped GL-style; the Vulkan Y-flip
  is applied only when `SceneContext` is filled (`DotPathResolver.cpp:37`).

## Design

### UI tree

Canvases and elements are entities. The tree reuses `HierarchyComponent`, so
`destroyEntity` already cascades to children. UI entities carry no
`MeshComponent` / `RenderableTag`, so `FrameGraphRenderer` never draws them.

| Component | Fields |
|---|---|
| `UICanvas` | `mode` (`ScreenOverlay` / `WorldTexture`), `sortOrder`, `referenceSize`, `scaleMode` (`ConstantPixel` / `ScaleWithScreen`). In world mode: `pixelSize`, `clearColor`, `textureSlot` (default `emissiveMap`), and the runtime target texture. |
| `UIRect` | `anchorMin`, `anchorMax`, `pivot`, `anchoredPosition`, `sizeDelta`, `visible`. Computed: `rect` and `clip` in canvas pixels, y down. |
| `UIImage` | `texture` (none = white), `color`, `uvRect`, `raycastTarget` |
| `UIPanel` | 9-slice: `texture`, `color`, `border` (L, T, R, B), `fillCenter` |
| `UIText` | UTF-8 `text`, `font`, `size`, `color`, `hAlign`, `vAlign`, `wrap`, `lineSpacing`, plus a cached layout |
| `UIClip` | Marker: children are clipped to this element's rect. |
| `UIInteractable` | `interactable`, `hovered`, `pressed`, one-frame `clicked` / `valueChanged`, and state colours |
| `UIButton`, `UIToggle`, `UISlider` | Widget state: `isOn` + checkmark entity; `min`, `max`, `value` + fill and handle entities |

### CPU modules

These have no Vulkan dependency, so they are tested without a GPU:

- `CanvasLayout`: rect resolution and nested clip intersection.
- `Utf8`: decoding, with invalid bytes → U+FFFD.
- `GlyphAtlasPacker`: a shelf packer.
- `SdfFont`: `stbtt_GetCodepointSDF` (already in the vendored stb v1.26).
  Glyphs are baked at 48 px, with padding 6 and an on-edge value of 180;
  any font size is drawn by scaling.
- `TextLayout`: lines, wrapping, alignment, kerning and the fallback glyph.
- `UIBatchBuilder`:
  - Walks each canvas depth-first and emits vertices, indices and batches,
    in painter's order.
  - A batch breaks on (image view, scissor). Text and plain quads don't
    break batches.
- `UIHitTest`: the topmost element under a point, respecting clips and
  `raycastTarget`.
- `CameraRay` (`include/ECS/CameraRay.h`): `screenPointToRay`, and a hit on a
  quad's local z = 0 plane, mapped to canvas UV and then to a canvas pixel.

### Systems

All run after Transform and Camera (priority 0). Each sets its priority in its
constructor. `SystemManager` switches to `std::stable_sort`, because
`ApplicationBase` currently assigns priorities after insertion.

| Priority | System | Work |
|---|---|---|
| 50 | `CanvasInputSystem` | Hit tests against last frame's rects (what the user saw): overlay canvases first by `sortOrder`, then world canvases by nearest ray hit. Sets hover and press, and click on press + release over the same element. Holds the pointer while pressed so a slider keeps dragging. Updates toggle and slider values. Uses the screen centre while the mouse is captured. |
| 51 | `CanvasLayoutSystem` | Resolves `UIRect`s from each canvas root. |
| 52 | `CanvasTextSystem` | Lays out text that changed and rasterises missing glyphs. |

Script code reads `clicked` / `valueChanged` in the following `on_update`,
which is one frame after the click. This latency is documented.

### GPU side

`UIRenderer` lives in `UIContext`, which also owns fonts and the glyph atlas.
`ApplicationBase` owns the `UIContext`.

- `FrameRingBuffer` (`include/GPU/`): one persistently mapped buffer per frame
  in flight, used for vertices, indices and staging, with linear allocation.
  When it grows, the old buffer is retired through `GpuDeleteQueue::adopt`.
- Glyph atlas: a 2048² `R8_UNORM` texture filled by copies from the ring.
  When it is full it is cleared and every text is re-laid out.
- Pipelines are built with `PipelineStateBuilder` and cached per colour
  format. They use premultiplied alpha and dynamic viewport and scissor.
- Shaders `ui.vert` / `ui.frag`:
  - The vertex shader maps pixel positions to NDC through a `targetSize`
    push constant.
  - In mode 0 the fragment shader multiplies the image by the vertex colour.
    Mode 1 samples the SDF atlas and uses `smoothstep` with `fwidth`.
  - The output is premultiplied.
  - The shaders ship next to the default pipeline and are found the way the
    IBL shaders are.

Per frame, between `record(cmd)` and `m_renderGraph->execute`:

1. Reset the ring and copy pending glyphs into the atlas.
2. Build the batches for every canvas.
3. For each world canvas:
   - barrier → `COLOR_ATTACHMENT`;
   - `vkCmdBeginRendering` with a clear to `clearColor`;
   - draw the batches;
   - barrier → `SHADER_READ_ONLY` (destination: fragment shader).

The graph then runs. Geometry passes sample world-canvas textures as ordinary
material textures. The `UIOverlay` pass draws the screen canvases in
`sortOrder`.

### World canvases

`create_world_canvas` creates:

- a target texture (`R8G8B8A8_SRGB`, COLOR_ATTACHMENT | SAMPLED);
- a quad in the standard `Vertex` format;
- a `MaterialComponentV5` whose `textureSlot` points at the target. The
  default is emissive with a black albedo; `albedoMap` gives a lit panel.

The quad has `castShadows = false`, and its transform scale sets its world size.

When a canvas is destroyed:

- its texture is released from the material descriptor cache through a new
  `RenderGraph::releaseMaterialTexture(VkImageView)`;
- the texture is freed after `maxFramesInFlight` frames.

### Default pipeline

Tonemap's swapchain output keeps `color_write` but drops `present`. A last pass
is appended:

```json
{
  "name": "UIOverlay",
  "type": "graphics",
  "execution": { "type": "ui_canvas" },
  "outputs": [ { "resource": "swapchain", "usage": "color_blend", "present": true } ]
}
```

Example pipelines are left alone. Other pipelines opt in by adding the same
pass. If screen canvases exist but no pipeline pass draws them, the engine
logs a warning once.

### Python

```python
ui = engine.ui
hud = ui.create_canvas(reference_size=(1920, 1080), scale_mode=sk.CANVAS_SCALE_WITH_SCREEN)
panel = ui.create_panel(hud, texture="ui/panel.png", border=(12, 12, 12, 12))
ui.set_rect(panel, anchor_min=(.5, .5), anchor_max=(.5, .5), pivot=(.5, .5),
            position=(0, 0), size=(420, 300))
ui.set_clip(panel, True)
ui.create_text(panel, "Śūnyākāśa — Привет", font="fonts/Roboto-Regular.ttf", size=28)
play = ui.create_button(panel, "Play")
exposure = ui.create_slider(panel, min=-2, max=2, value=0)
term = ui.create_world_canvas(pixel_size=(1024, 512), world_size=(2, 1),
                              position=(0, 1.5, -3))

def on_update(dt):
    if ui.was_clicked(play):
        ...
    if ui.value_changed(exposure):
        engine.set_custom_float("default.exposure", ui.slider_value(exposure))
    if not ui.pointer_over_ui:
        ...  # game input
```

Further calls: `set_text`, `set_color`, `set_visible`, `is_hovered`,
`is_pressed`, `create_toggle`, `toggle_value`, `set_toggle_value`,
`set_slider_value`, `set_image_texture`. Elements are destroyed with
`scene.destroy_entity`, which removes children too.

The C++ side is `include/Facade/UIAPI.h`. It has a registry-only constructor
for tests, like `EcsAPI`.

## Milestones

Each milestone is tested before the next starts. The full C++ and Python
suites run before and after each one.

1. **Plumbing:**
   - the `ui_canvas` execution kind;
   - `CameraRay`;
   - `stable_sort` in `SystemManager`.
2. **Layout:** the components and `CanvasLayoutSystem`.
3. **CPU text:** UTF-8, the packer, `SdfFont` and `TextLayout`.
4. **CPU batching:** `UIBatchBuilder` (9-slice, ordering, merging, scissor).
5. **Screen overlay on the GPU:**
   - `FrameRingBuffer`, atlas uploads and `UIRenderer`;
   - the `UIOverlay` pass in the default pipeline.
6. **World canvases:**
   - targets, the quad and the material slot;
   - `releaseMaterialTexture` and deferred destruction.
7. **Input and widgets:** `UIHitTest`, `CanvasInputSystem`, Button, Toggle
   and Slider.
8. **Python and examples:**
   - the facade and Cython bindings;
   - `ui_canvas_demo`;
   - `docs/guides/canvas-ui.md` and `docs/api/python/ui.md`.

- **Python unittest:** `tests/python/test_ui.py` checks:
  - the API inventory;
  - that the default pipeline still validates;
  - the new constants.
- **End to end:** run `ui_canvas_demo` with `SHOONYAKASHA_VALIDATION=1`.
  - The screen HUD and the world terminal render.
  - Both take clicks: with the cursor, and with the centre crosshair while
    the mouse is captured.
  - The validation layers report nothing.
  - Then rerun sprite_ui_test, pong and dakini_temple to check they look the
    same.

## Known limits

- Without HarfBuzz there is no shaping, so Devanagari and Tibetan render
  incorrectly. The dakini temple keeps its pre-rendered labels until shaping
  is added.
- An emissive world canvas goes through auto-exposure and bloom; the
  `albedoMap` slot avoids that. Transparent world canvases are not
  supported yet; use opaque or alpha-masked ones.
- World-canvas hit tests don't check whether 3D geometry is in the way.
- When the glyph atlas fills it is cleared and rebuilt rather than evicting
  least-recently-used glyphs.
- The UI renderer owns its shaders and pipeline state rather than reading them
  from pipeline JSON. That keeps world canvases working under any pipeline.
